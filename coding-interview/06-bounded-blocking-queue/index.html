    6. Bounded Blocking Queue¶

    L2 ★★☆ · ReentrantLock + two Conditions · circular buffer · LeetCode 1188

    Problem¶

    Implement a thread-safe bounded queue: put(e) blocks while the queue is full, take() blocks while it's empty, and offer(e, timeout) gives up after the timeout. Don't use java.util.concurrent collections.

    This is the most-asked "build it yourself" question, because the bounded queue is the backbone of producer/consumer systems, thread pools, and backpressure.

    Key idea¶

    • Storage: a fixed array used as a circular buffer (head, tail, count). Both operations are O(1) with no allocation.
    • Coordination: one lock, two wait-sets: producers wait on notFull, and consumers wait on notEmpty. A put wakes one consumer, and a take wakes one producer.

    After put the tail moves to slot 0 (it wraps around: (7 + 1) % 8). After take the head moves to slot 3.

    sequenceDiagram autonumber participant P as Producer participant Q as Queue (lock) participant C as Consumer C->>Q: take(): count==0 → notEmpty.await() P->>Q: put(x): enqueue, count=1 P->>C: notEmpty.signal() C->>Q: wakes, reacquires lock, re-checks count>0 → dequeue C->>P: notFull.signal()

    Code walkthrough¶

    Fields and constructor¶

        private final Object[] items;                 // circular buffer
    private int head;                             // next slot to take from
    private int tail;                             // next slot to put into
    private int count;                            // number of elements
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();   // producers wait here
    private final Condition notEmpty = lock.newCondition();  // consumers wait here

    public BoundedBlockingQueue(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be > 0");
        items = new Object[capacity];
    }
    • head, tail, and count are all guarded by lock. Write that comment in the interview. It shows you think about ownership.
    • Keeping count separately avoids the classic ambiguity of head == tail, which can mean either full or empty.

    put / take¶

        public void put(E e) throws InterruptedException {
        if (e == null) throw new NullPointerException();
        lock.lockInterruptibly();                 // a blocked producer can still be cancelled
        try {
            while (count == items.length) {
                notFull.await();                  // queue full → wait for a consumer
            }
            enqueue(e);
            notEmpty.signal();                    // exactly one consumer can now make progress
        } finally {
            lock.unlock();
        }
    }

    public E take() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            while (count == 0) {
                notEmpty.await();                 // queue empty → wait for a producer
            }
            E e = dequeue();
            notFull.signal();                     // exactly one producer can now make progress
            return e;
        } finally {
            lock.unlock();
        }
    }
    Code Why
    lock.lockInterruptibly() A producer blocked trying to get the lock can still be cancelled with interrupt(). Plain lock() would ignore it.
    while (count == items.length) notFull.await(); Guarded wait. await releases the lock, parks, and reacquires the lock before returning. Use while because of spurious wake-ups and because another producer may have filled the slot first.
    notEmpty.signal() after enqueue One new item means one consumer can progress, so use signal rather than signalAll (it's safe because all waiters on notEmpty wait for the same condition).
    finally { lock.unlock(); } Unlock on every path, including InterruptedException from await().

    Timed offer¶

        /** Timed offer: gives up after the timeout. awaitNanos returns the time still left. */
    public boolean offer(E e, long timeout, TimeUnit unit) throws InterruptedException {
        long nanos = unit.toNanos(timeout);
        lock.lockInterruptibly();
        try {
            while (count == items.length) {
                if (nanos <= 0) return false;
                nanos = notFull.awaitNanos(nanos);
            }
            enqueue(e);
            notEmpty.signal();
            return true;
        } finally {
            lock.unlock();
        }
    }

    awaitNanos(n) returns the remaining time. Looping with the returned value handles spurious wake-ups correctly without extending the total timeout. That detail separates good answers from great ones.

    Helpers¶

        private void enqueue(E e) {                   // caller holds lock
        items[tail] = e;
        tail = (tail + 1) % items.length;
        count++;
    }

    @SuppressWarnings("unchecked")
    private E dequeue() {                         // caller holds lock
        E e = (E) items[head];
        items[head] = null;                       // let GC reclaim it
        head = (head + 1) % items.length;
        count--;
        return e;
    }

    public int size() {
        lock.lock();
        try { return count; } finally { lock.unlock(); }
    }

    items[head] = null prevents a memory leak: without it, the array keeps references to objects that were already taken.

    Why two Conditions beat wait/notifyAll¶

    With a single monitor, producers and consumers share one wait-set, so you must notifyAll. That wakes producers when only consumers can make progress. Two conditions let you signal exactly the right side. (This is how java.util.concurrent.ArrayBlockingQueue is built.)

    Run it¶

    20 producers × 5,000 items flow through a capacity of 8 (heavy blocking), with 10 consumers, all on virtual threads:

    20 producers x 5000 items through capacity 8: sum=250050000 (expected 250050000), timed offer on full queue=false
PASS

    Common mistakes¶

    • if instead of while around await().
    • signal() called before the state change, or outside the lock (IllegalMonitorStateException).
    • Unbounded ArrayList storage: that's not a bounded queue.
    • Using synchronized + wait() with thousands of virtual threads on JDK 21–23: Object.wait() pins carriers. Condition.await() doesn't.

    Follow-up questions¶

    How would you get more throughput?

    Use two locks, one for put (tail) and one for take (head), with an atomic count, like LinkedBlockingQueue. Producers and consumers then don't contend with each other.

    How do you add drainTo / batch take?

    Take the lock once, dequeue up to max items, then notFull.signalAll() (several producers can now proceed).

    Why lockInterruptibly but lock() in size()?

    size() never waits for a condition, so it holds the lock only briefly, and there's nothing worth interrupting.

    Full source: BoundedBlockingQueue.java 
    import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.LongAdder;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

/**
 * LeetCode 1188 / classic: implement a bounded blocking queue with put/take (+ timed offer) from scratch.
 * Run: java BoundedBlockingQueue.java
 */
public class BoundedBlockingQueue<E> {

    private final Object[] items;                 // circular buffer
    private int head;                             // next slot to take from
    private int tail;                             // next slot to put into
    private int count;                            // number of elements
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();   // producers wait here
    private final Condition notEmpty = lock.newCondition();  // consumers wait here

    public BoundedBlockingQueue(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be > 0");
        items = new Object[capacity];
    }

    public void put(E e) throws InterruptedException {
        if (e == null) throw new NullPointerException();
        lock.lockInterruptibly();                 // a blocked producer can still be cancelled
        try {
            while (count == items.length) {
                notFull.await();                  // queue full → wait for a consumer
            }
            enqueue(e);
            notEmpty.signal();                    // exactly one consumer can now make progress
        } finally {
            lock.unlock();
        }
    }

    public E take() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            while (count == 0) {
                notEmpty.await();                 // queue empty → wait for a producer
            }
            E e = dequeue();
            notFull.signal();                     // exactly one producer can now make progress
            return e;
        } finally {
            lock.unlock();
        }
    }

    /** Timed offer: gives up after the timeout. awaitNanos returns the time still left. */
    public boolean offer(E e, long timeout, TimeUnit unit) throws InterruptedException {
        long nanos = unit.toNanos(timeout);
        lock.lockInterruptibly();
        try {
            while (count == items.length) {
                if (nanos <= 0) return false;
                nanos = notFull.awaitNanos(nanos);
            }
            enqueue(e);
            notEmpty.signal();
            return true;
        } finally {
            lock.unlock();
        }
    }

    private void enqueue(E e) {                   // caller holds lock
        items[tail] = e;
        tail = (tail + 1) % items.length;
        count++;
    }

    @SuppressWarnings("unchecked")
    private E dequeue() {                         // caller holds lock
        E e = (E) items[head];
        items[head] = null;                       // let GC reclaim it
        head = (head + 1) % items.length;
        count--;
        return e;
    }

    public int size() {
        lock.lock();
        try { return count; } finally { lock.unlock(); }
    }

    public static void main(String[] args) throws Exception {
        var q = new BoundedBlockingQueue<Integer>(8);              // tiny capacity → lots of blocking
        int producers = 20, perProducer = 5_000;
        LongAdder sum = new LongAdder();
        try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int p = 0; p < producers; p++) {
                ex.submit(() -> { for (int i = 1; i <= perProducer; i++) q.put(i); return null; });
            }
            for (int c = 0; c < 10; c++) {
                ex.submit(() -> { for (int i = 0; i < producers * perProducer / 10; i++) sum.add(q.take()); return null; });
            }
        }
        long expected = (long) producers * perProducer * (perProducer + 1) / 2;
        if (sum.sum() != expected || q.size() != 0) throw new AssertionError(sum.sum() + " vs " + expected);
        boolean accepted = new BoundedBlockingQueue<Integer>(1) {{ put(1); }}.offer(2, 50, TimeUnit.MILLISECONDS);
        if (accepted) throw new AssertionError("offer on a full queue must time out");
        System.out.printf("20 producers x 5000 items through capacity 8: sum=%d (expected %d), timed offer on full queue=%s%n",
                sum.sum(), expected, accepted);
        System.out.println("PASS");
    }
}
