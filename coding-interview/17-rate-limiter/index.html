    17. Token Bucket Rate Limiter¶

    L3 ★★☆ · lazy refill · sleep outside the lock

    Problem¶

    Implement a rate limiter that allows on average R requests per second with bursts of up to B. Provide a non-blocking tryAcquire() (for an API that returns 429) and a blocking acquire() (for a client that must pace itself).

    Key idea: the token bucket¶

    The bucket holds at most B tokens and gains R tokens per second. Each request takes one token, and an empty bucket means wait or reject. Instead of a background thread adding tokens, compute them lazily from the elapsed time on every call:

    tokens = min(B, tokens + (now - lastRefill) × R)
    flowchart LR T[time passes] -->|+R tokens/s, capped at B| BK[(bucket<br/>0..B tokens)] REQ[request] --> D{tokens ≥ 1?} BK --> D D -->|yes| OK[take 1 token → allowed] D -->|no, tryAcquire| NO[reject → 429] D -->|no, acquire| W[sleep until 1 token exists → retry]
    xychart-beta title "Tokens over time: burst 10, 100/s, greedy clients" x-axis "ms" [0, 1, 10, 20, 30, 40, 50] y-axis "tokens" 0 --> 10 line [10, 0, 1, 1, 1, 1, 1]

    The bucket starts full, so the first 10 requests pass instantly (the burst). After that, the rate settles at one token every 10 ms.

    Code walkthrough¶

        private final long capacity;
    private final double refillPerNano;
    private final ReentrantLock lock = new ReentrantLock();
    private double tokens;                            // guarded by lock
    private long lastRefillNanos;                     // guarded by lock

    public TokenBucketRateLimiter(long capacity, long tokensPerSecond) {
        this.capacity = capacity;
        this.refillPerNano = tokensPerSecond / 1_000_000_000.0;
        this.tokens = capacity;                       // start full → allows an initial burst
        this.lastRefillNanos = System.nanoTime();
    }

    /** Lazy refill: no background thread; tokens are computed from elapsed time on each call. */
    private void refill(long now) {
        tokens = Math.min(capacity, tokens + (now - lastRefillNanos) * refillPerNano);
        lastRefillNanos = now;
    }

    public boolean tryAcquire() {
        lock.lock();
        try {
            refill(System.nanoTime());
            if (tokens >= 1) {
                tokens -= 1;
                return true;
            }
            return false;
        } finally {
            lock.unlock();
        }
    }

    public void acquire() throws InterruptedException {
        while (true) {
            long waitNanos;
            lock.lock();
            try {
                refill(System.nanoTime());
                if (tokens >= 1) {
                    tokens -= 1;
                    return;
                }
                waitNanos = (long) Math.ceil((1 - tokens) / refillPerNano);   // time until 1 token exists
            } finally {
                lock.unlock();
            }
            Thread.sleep(Duration.ofNanos(waitNanos));   // sleep OUTSIDE the lock; cheap on a virtual thread
        }
    }
    Code Why
    double tokens Fractional tokens accumulate between calls (for example, 0.3 tokens after 3 ms at 100/s).
    refill(now) under the lock Read-modify-write of tokens and lastRefillNanos must be atomic.
    System.nanoTime() Monotonic. currentTimeMillis() can jump backwards (NTP), which would mint or burn tokens.
    tryAcquire() never waits For server-side admission control: reject immediately with 429 + Retry-After.
    acquire(): compute waitNanos, unlock, then sleep Sleeping while holding the lock would block every other caller, including tryAcquire. After waking, loop: another thread may have taken the token.
    Thread.sleep(Duration) Cheap on a virtual thread. 10,000 clients pacing themselves cost almost nothing.

    Run it¶

    tryAcquire: 50 greedy clients for 500 ms -> allowed 59 (expected ~60)
acquire: 101 permits at 200/s took 533 ms (expected ~500)
PASS

    Expected values: 10 (burst) + 0.5 s × 100/s = 60. For the blocking test, 1 initial token plus 100 more at 200/s ≈ 500 ms.

    Algorithm comparison (the follow-up you'll get)¶

    Algorithm Bursts Memory Accuracy
    Token bucket Allows up to B O(1) Good
    Leaky bucket Smooths to a constant rate O(1) or a queue Good
    Fixed window counter 2× burst at window edges O(1) Poor at edges
    Sliding window log None O(requests) Exact
    Sliding window counter Small O(1) Approximate, good
    Distributed rate limiting across 20 pods?

    A local bucket per pod with R/20 is simple but inaccurate when traffic is uneven. For accuracy, use a Redis Lua script that does refill+take atomically per key (one round trip), with fail-open or fail-closed decided per endpoint.

    Per-user limits?

    Use ConcurrentHashMap<UserId, TokenBucket> with computeIfAbsent. Evict idle buckets with Caffeine's expireAfterAccess, or the map grows forever.

    Can you make it lock-free?

    Yes: pack (tokens, timestamp) into an immutable object in an AtomicReference and CAS-loop the refill+take. It's worth it only under heavy contention.

    Full source: TokenBucketRateLimiter.java 
    import java.time.Duration;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.locks.ReentrantLock;

/**
 * Token-bucket rate limiter: capacity B (burst), refill R tokens/second. tryAcquire() never blocks; acquire() waits.
 * Run: java TokenBucketRateLimiter.java
 */
public class TokenBucketRateLimiter {

    private final long capacity;
    private final double refillPerNano;
    private final ReentrantLock lock = new ReentrantLock();
    private double tokens;                            // guarded by lock
    private long lastRefillNanos;                     // guarded by lock

    public TokenBucketRateLimiter(long capacity, long tokensPerSecond) {
        this.capacity = capacity;
        this.refillPerNano = tokensPerSecond / 1_000_000_000.0;
        this.tokens = capacity;                       // start full → allows an initial burst
        this.lastRefillNanos = System.nanoTime();
    }

    /** Lazy refill: no background thread; tokens are computed from elapsed time on each call. */
    private void refill(long now) {
        tokens = Math.min(capacity, tokens + (now - lastRefillNanos) * refillPerNano);
        lastRefillNanos = now;
    }

    public boolean tryAcquire() {
        lock.lock();
        try {
            refill(System.nanoTime());
            if (tokens >= 1) {
                tokens -= 1;
                return true;
            }
            return false;
        } finally {
            lock.unlock();
        }
    }

    public void acquire() throws InterruptedException {
        while (true) {
            long waitNanos;
            lock.lock();
            try {
                refill(System.nanoTime());
                if (tokens >= 1) {
                    tokens -= 1;
                    return;
                }
                waitNanos = (long) Math.ceil((1 - tokens) / refillPerNano);   // time until 1 token exists
            } finally {
                lock.unlock();
            }
            Thread.sleep(Duration.ofNanos(waitNanos));   // sleep OUTSIDE the lock; cheap on a virtual thread
        }
    }

    public static void main(String[] args) throws Exception {
        var limiter = new TokenBucketRateLimiter(10, 100);       // burst 10, 100/s
        AtomicInteger allowed = new AtomicInteger();
        long end = System.nanoTime() + Duration.ofMillis(500).toNanos();
        try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int c = 0; c < 50; c++) {                        // 50 greedy clients
                ex.submit(() -> { while (System.nanoTime() < end) { if (limiter.tryAcquire()) allowed.incrementAndGet(); Thread.onSpinWait(); } });
            }
        }
        // expected ≈ burst 10 + 0.5 s x 100/s = 60
        System.out.println("tryAcquire: 50 greedy clients for 500 ms -> allowed " + allowed.get() + " (expected ~60)");
        if (allowed.get() < 50 || allowed.get() > 70) throw new AssertionError();

        var blocking = new TokenBucketRateLimiter(1, 200);       // no burst, 200/s
        long t0 = System.nanoTime();
        try (var ex = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 101; i++) ex.submit(() -> { blocking.acquire(); return null; });
        }
        long ms = (System.nanoTime() - t0) / 1_000_000;
        System.out.println("acquire: 101 permits at 200/s took " + ms + " ms (expected ~500)");
        if (ms < 400 || ms > 1_500) throw new AssertionError();
        System.out.println("PASS");
    }
}
