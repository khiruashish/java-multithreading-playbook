    Enabling Virtual Threads in Spring Boot¶

    L2

    Version matrix¶

    Spring Boot Spring Framework Java VT support
    2.x 5.x 8–17 None. Upgrade first
    3.0–3.1 6.0 17+ Manual: customize TomcatProtocolHandlerCustomizer
    3.2+ 6.1+ 21+ spring.threads.virtual.enabled=true
    4.x 7.x 17+ (21+ for VTs) Same property. Jakarta EE 11, Jackson 3

    The one property¶

    application.yml (from examples/spring-boot-vt)
    spring:
  application:
    name: product-page-service
  threads:
    virtual:
      enabled: true            # Tomcat request threads, @Async, @Scheduled run on virtual threads
  main:
    keep-alive: true           # virtual threads are daemons; keep the JVM alive

server:
  port: 8080
  shutdown: graceful           # finish in-flight requests on SIGTERM
  tomcat:
    threads:
      max: 200                 # ignored for request handling when virtual threads are on
    accept-count: 1000

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus,threaddump
  endpoint:
    health:
      probes:
        enabled: true

playbook:
  concurrency:
    admission:
      max-in-flight: 5000              # Little's Law: peak RPS x p99 latency x headroom
    fan-out-timeout: 800ms             # deadline for the whole product-page fan-out
    cpu-pool-size: 0                   # 0 = availableProcessors()
    bulkheads:
      catalog:   { max-concurrent: 200, max-wait: 50ms }
      pricing:   { max-concurrent: 100, max-wait: 50ms }
      inventory: { max-concurrent: 100, max-wait: 50ms }
  downstream:
    base-url: http://localhost:8080/sim
    self-hosted: true                  # call our own /sim endpoints on whatever port we bound
    connect-timeout: 500ms
    read-timeout: 1s
  simulation:
    catalog-latency: 120ms
    pricing-latency: 80ms
    inventory-latency: 60ms

logging:
  pattern:
    level: "%5p [%X{requestId:-}]"

    With spring.threads.virtual.enabled=true, Spring Boot configures:

    Component What runs on virtual threads
    Tomcat / Jetty Every HTTP request handler
    applicationTaskExecutor @Async methods and AsyncTaskExecutor injection. A SimpleAsyncTaskExecutor that starts a new VT per task
    Task scheduler @Scheduled methods (SimpleAsyncTaskScheduler)
    Kafka / RabbitMQ / JMS / Pulsar listener containers Listener invocations
    Spring Data Redis Cluster command executor
    Spring for GraphQL / Spring WebMVC async Async request processing

    server.tomcat.threads.max no longer limits concurrency

    With VTs on, Tomcat doesn't use its worker pool for requests. Limit concurrency with an admission filter (Resilience) and with server.tomcat.max-connections (default 8192).

    Doing it manually (Spring Boot 3.0/3.1, or custom containers)¶

    @Bean
TomcatProtocolHandlerCustomizer<?> virtualThreadsForTomcat() {
    return handler -> handler.setExecutor(Executors.newVirtualThreadPerTaskExecutor());
}

@Bean(TaskExecutionAutoConfiguration.APPLICATION_TASK_EXECUTOR_BEAN_NAME)
AsyncTaskExecutor applicationTaskExecutor() {
    return new TaskExecutorAdapter(Executors.newVirtualThreadPerTaskExecutor());
}

    Verifying it's on¶

    curl -s localhost:8080/api/debug/thread
# {"name":"tomcat-handler-12","isVirtual":true,"toString":"VirtualThread[#65,tomcat-handler-12]/runnable@ForkJoinPool-1-worker-3"}

    The sample's integration test asserts this:

    ProductPageIntegrationTest.java (excerpt)
    @Test
void requestsAreServedByVirtualThreads() {
    Map<String, Object> body = client.get().uri("/api/debug/thread").retrieve().body(MAP);
    assertThat(body).containsEntry("isVirtual", true);
}

    Concurrency beans in the sample¶

    ConcurrencyConfig.java
    package com.playbook.vt.config;

import com.playbook.vt.concurrency.AdmissionControlFilter;
import com.playbook.vt.concurrency.FanOut;
import com.playbook.vt.concurrency.PinningMonitor;
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.binder.jvm.ExecutorServiceMetrics;
import org.springframework.boot.web.servlet.FilterRegistrationBean;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.Ordered;

import java.time.Duration;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

@Configuration(proxyBeanMethods = false)
public class ConcurrencyConfig {

    /** Fan-out helper whose subtasks run on named virtual threads ("fanout-0", "fanout-1", ...). */
    @Bean
    FanOut fanOut() {
        return new FanOut("fanout-");
    }

    /**
     * Bounded PLATFORM pool for CPU-heavy work (image resize, PDF, scoring). Virtual threads are not preempted, so
     * long CPU work on them would starve the carriers that every request depends on.
     */
    @Bean(destroyMethod = "close")
    ExecutorService cpuExecutor(ConcurrencyProperties props, MeterRegistry registry) {
        int size = props.cpuPoolSize() > 0 ? props.cpuPoolSize() : Runtime.getRuntime().availableProcessors();
        ThreadPoolExecutor pool = new ThreadPoolExecutor(size, size, 0, TimeUnit.SECONDS,
                new ArrayBlockingQueue<>(size * 50),
                Thread.ofPlatform().name("cpu-", 0).factory(),
                new ThreadPoolExecutor.CallerRunsPolicy());
        return ExecutorServiceMetrics.monitor(registry, pool, "cpu");
    }

    @Bean
    FilterRegistrationBean<AdmissionControlFilter> admissionControlFilter(ConcurrencyProperties props) {
        var reg = new FilterRegistrationBean<>(new AdmissionControlFilter(props.admission().maxInFlight()));
        reg.setOrder(Ordered.HIGHEST_PRECEDENCE);
        reg.addUrlPatterns("/*");
        return reg;
    }

    @Bean
    PinningMonitor pinningMonitor(MeterRegistry registry) {
        return new PinningMonitor(registry, Duration.ofMillis(10));
    }
}
    HttpClientConfig.java
    package com.playbook.vt.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.client.JdkClientHttpRequestFactory;
import org.springframework.web.client.RestClient;

import java.net.http.HttpClient;
import java.util.concurrent.Executors;

@Configuration(proxyBeanMethods = false)
public class HttpClientConfig {

    /**
     * JDK HttpClient whose internal async tasks also run on virtual threads. Blocking {@code send()} from a virtual
     * thread parks it (no carrier is held). Timeouts are mandatory: a VT blocked forever is still a leak.
     */
    @Bean(destroyMethod = "close")
    HttpClient jdkHttpClient(DownstreamProperties props) {
        return HttpClient.newBuilder()
                .executor(Executors.newVirtualThreadPerTaskExecutor())
                .connectTimeout(props.connectTimeout())
                .version(HttpClient.Version.HTTP_1_1)
                .build();
    }

    @Bean
    RestClient downstreamRestClient(RestClient.Builder builder, HttpClient jdkHttpClient, DownstreamProperties props) {
        var factory = new JdkClientHttpRequestFactory(jdkHttpClient);
        factory.setReadTimeout(props.readTimeout());
        return builder.requestFactory(factory).build();
    }
}

    Java 25 with preview features (optional)¶

    To use StructuredTaskScope in a Boot app, enable preview for compile, test, and run:

    <plugin>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration><compilerArgs><arg>--enable-preview</arg></compilerArgs></configuration>
</plugin>
<plugin>
  <artifactId>maven-surefire-plugin</artifactId>
  <configuration><argLine>--enable-preview</argLine></configuration>
</plugin>

    java --enable-preview -jar app.jar

    Keep preview usage behind one facade (like the sample's FanOut) so a JDK upgrade touches one class.
